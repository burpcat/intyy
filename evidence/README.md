# Evidence index

This folder holds published copies of real intyy runs and records. It follows build plan §11.
The owner checks each row against the files. `intyy evidence verify` checks hashes, links, forbidden files, and canaries.

**Status values.** `pending` means the file does not exist yet. `published` means it exists and `evidence verify` is clean. A row stays `pending` until the owner publishes it.

## Honesty notes

- **One person played every staff ID.** Identity is self-declared in this build.
- **Runs before M09 have the model rungs 2 and 3 switched off.** Each run's frozen `ladder` facts say so.
- **Discovery runs differ each time.** A model run cannot be regenerated byte for byte. The published run is the proof.
- **Drills are never approval-grade.** B1 and B5 are drills, in set B below. Only items that were run and verified stay in this index.
- **A10 depends on the bank app.** If the button is hidden from restricted users, the run escalates instead of failing. Publish what happens.
- **Results are not in this file.** The columns say what each item shows and where its file lives. Read the run's `result.json` for the outcome.

## Layout

```
evidence/
  README.md                         this index
  manifest.json                     intyy.publish/1.0
  artifacts/kvfcu/<cap>/<version>/  copies of the sealed artifacts the runs used
  keystone/
    runs/<run_id>/                  mirrors state/evidence
    batches/<batch_id>/             plan.json, report.json
  tests/safety.json                 A12
```

The folder names `artifacts`, `trust`, and `tests` are reserved. Trust snapshots (B3) live under `trust/scores/keystone/`. Budget: 60 MB for the whole folder.
